## Goal

## Standard workflow

1. Inspect relevant repository files before substantial project work.
2. Create changes on a scoped branch when risk or breadth warrants review.
3. Use commits that state the subsystem and intent.
4. Use PRs for structural changes, OS revisions, schemas, or cross-subsystem changes.
5. Direct commits may be used for small documentation/canon corrections when explicitly appropriate.
6. Preserve existing artifacts; version rather than silently replace.
