# UNIVERSE OS V1.2 — MIGRATION PLAN V1

## Strategy
V1.2 is additive-first.

Existing V1.1 JSON remains active until V1.2 acceptance. New V2 files mirror/extend current truth, allowing side-by-side regression.

## Sequence
1. freeze baseline;
2. create ontology and domain V2 records;
3. derive Atlas-native relationship graph;
4. classify world memory;
5. add civilization/institution records;
6. add mutation/query/visual contracts;
7. replay Weeks 1–3;
8. run acceptance;
9. only then update Project Control Registry and active release status.

## Compatibility
Legacy/current IDs remain stable wherever possible. V2 must reference existing location, route, character, region and division IDs instead of renaming them.

## Rollback
On blocking regression, consumers remain on V1.1 and V2 branch history is retained for repair.
