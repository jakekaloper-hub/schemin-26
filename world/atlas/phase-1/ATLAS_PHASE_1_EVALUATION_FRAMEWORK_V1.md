# ATLAS PHASE 1 EVALUATION FRAMEWORK V1

**Status:** PHASE 1 ANALYST CONTROL

## Baseline invariants

Must remain:
- 7 physical zones;
- 3 2026 Division overlays;
- 12/12 owner-world coverage;
- 23 pre-Phase-1 active locations preserved;
- 18 pre-Phase-1 routes preserved;
- current character canon untouched.

Candidate growth does not count as active-location growth.

## 1. Canon continuity score

Target: 100% on hard constraints.

Checks:
- correct zone;
- correct owner/home;
- correct Division membership;
- current character identity;
- persistent state respected;
- no candidate presented as permanent without promotion.

Any hard-canon failure = page/gate reject.

## 2. Location reuse quality

Metric:
percentage of scenes where the selected existing site/sub-location was preferred over unnecessary new geography.

Target:
new locations should be justified, not maximized.

Warning:
a high raw reuse percentage is not automatically good if it produces repetitive settings.

## 3. Candidate utility

For each candidate:
- unique story function;
- plausible zone;
- event eligibility;
- tech translation;
- no active duplicate;
- future reuse potential.

Candidate without distinct function receives HOLD or REJECT.

## 4. Future-unlock readiness

A candidate is production-ready only if:
- status allows;
- zone is known or bounded;
- technology is resolved;
- activation trigger is explicit;
- no duplicate function;
- route requirement is understood.

Target: 100% of production-selected candidates.

## 5. Division flavor score

Evaluate scenes without visible labels:
- food/hospitality;
- material culture;
- roadside/social institutions;
- behavior/ritual.

Target:
Division identity should be inferable without changing terrain into food imagery.

## 6. Modernity compatibility

Score each modernity site:
- recognizable modern function;
- Schemin-native execution;
- technology compliance;
- tone compliance;
- reusable story value.

Reject if recognition depends on prohibited technology.

## 7. Special-event clarity

Every neutral special-event site must declare:
- venue tier;
- event eligibility;
- neutrality;
- route access;
- rarity rule.

Championship-only candidates must fail any non-championship selection test.

## 8. Historical persistence

For a returning site:
- prior event memory loaded;
- damage/cleanup state loaded;
- artifacts not magically reset;
- reputation remembered where narratively relevant.

Target: zero unexplained resets.

## 9. Random-backdrop reduction

Track:
number of pages whose setting was invented during image prompting rather than resolved before generation.

Target: **0**.

## 10. Map cohesion

Before release, verify:
- no duplicate city with same function/zone;
- no impossible route;
- no silent physical-zone move;
- no unsupported new biome;
- no candidate auto-promoted by renderer.

## 11. Production efficiency

Track:
- world-packet completion before prompting;
- number of prompt retries caused by location ambiguity;
- number of canon corrections after artwork;
- percent of scenes using reusable location packets.

Desired direction:
fewer ambiguity retries and fewer post-render corrections.

## 12. Season-evolution health

At weekly post-production, record:
- candidates revealed;
- candidates promoted;
- active locations changed;
- historical landmarks created;
- world-state mutations;
- retired/rejected candidates.

The map should evolve gradually with the season rather than exploding in Week 4.

## Phase 1 acceptance thresholds

- hard canon checks: 100%;
- owner coverage: 12/12;
- preexisting locations/routes lost: 0;
- active/candidate store conflation: 0;
- non-championship access to championship site: 0;
- random backdrop creation: 0;
- unresolved technology falsely treated as active: 0.

**Analyst doctrine:** optionality may grow quickly; canon should grow carefully.
