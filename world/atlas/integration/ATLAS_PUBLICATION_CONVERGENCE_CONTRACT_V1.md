Schemin does **not** need another world foundation.

The repository already contains:
- World Engine V1.1;

- three nonexclusive Division overlays;
- 12 owner-domain relationships;
- 23 active locations;

- 12 Homeland Cards;
- 23 Location Cards;

The missing layer is **publication convergence**: one contract that states how those released systems cooperate during weekly factual ingestion, world translation, prose, visual production, publication, and world-state writeback.

This contract supplies that layer without creating a second canon database.

## 4. Critical correction to the original Atlas brief

The original framing proposed three primary Divisional territories.

That is superseded by World Engine V1.1.

### Physical world
The persistent world is organized by **seven physical zones**.

### Division layer
Burgers, Wings and Pizza are **League-cultural/home-venue overlays**, not sealed countries, species borders or residential segregation.

This preserves:
- distinct owner biomes;
- TDS/Chili cross-divisional coexistence;
- neutral institutions;
- shared roads;
- travel logic;
- the possibility that a Division's culture appears in multiple physical zones.

The world determines the image; the image does not determine the world.

## 7. Cross-OS production law

### Weekly Memo OS
For every location-bearing page:

`verified matchup → event class → venue resolver → Location Control Plane → Memo Location Packet → character render contract → page brief → generation`

Memo may reveal new location evidence. It may not silently promote it.

### Novel OS
For every location-bearing scene:

`verified event/historical context → active LOC-* → Novel Location Packet → route/state/history → character/relationship/POV hydration → scene architecture → prose`

Novel invention becomes canon only through proposal and approval.

### Visual Production
Visual generation must receive:
1. character authority/reference packet;
2. world/location packet;
3. current state/history;
4. structural environment reference where available;
5. consumer-specific art direction.

The renderer may stylize. It may not relocate, redesign, reset history or promote generated scenery.

### Weekly World Evolution
After an accepted release:
- extract supported state/history changes;
- dry-run them;
- require the appropriate authority approvals;
- apply accepted changes;
- rebuild dependent packets/references/Atlas;
- rehydrate the next Memo/Novel cycle.

This creates the desired loop:

**real league event → story event → published artifact → governed world memory → future story depth.**

## 11. Acceptance criteria

The convergence baseline passes when:

### Universe OS / World Engine
Can resolve where an event happens, how participants arrive, what the place remembers, and what cannot be invented.

### Novel OS
Can hydrate a scene from the same world identity used by the Memo while retaining narrative-specific POV constraints.

### Weekly Memo OS
Can resolve recurring geography and current world state before page generation.

### Visual Production
Can consume location + character grounding without using its own output as canon.

### Character Canon
Remains authoritative for the Twelve's principal identities.

### Publication Release
Can distinguish verified fact, world translation, narrative interpretation and generated presentation.

### Weekly Evolution
Can transact supported post-release changes without auto-promoting candidates.
