**Origin:** Week 2 Blank-Canvas Acceptance Test forensic audit  
**Effective:** 2026-09-27

## Purpose

The Week 2 acceptance test proved that prose-only character prompting can preserve story intent while corrupting canonical identity. This patch makes reference fidelity a release-blocking subsystem.

## 1. Absolute visual authority

The commissioner-approved twelve-owner lineup/reference plate is the absolute visual identity authority for all twelve league characters. Written Character Canon v2 supplements details not clearly visible in the plate; it may not be used to reinterpret a visible identity.

A prior generated page, team name, nickname, matchup premise, or generic archetype is never identity authority.

## 2. Mandatory execution chain

Every visual containing a league owner MUST execute:

`OWNER_RESOLUTION → REFERENCE_RESOLUTION → CHARACTER_PACKET_LOCK → CONTINUITY_STATE_RESOLUTION → REFERENCE_ATTACHED_GENERATION → CHARACTER_QA → PAGE_QA`

No stage may be skipped. Team name or prose alone may never generate a league character.

## 3. Character packets

Memo OS maintains one persistent CHARACTER_PACKET per owner containing, at minimum:

- owner identity and current team mapping
- canonical character name
- approved reference crop / reference coordinates
- species and body architecture
- head / face architecture
- hair / fur / scales
- wardrobe and material language
- primary palette
- signature equipment and companions
- silhouette and scale
- required features
- forbidden mutations
- current continuity state

Character identity is immutable. Scene, pose, action, camera, expression, environment, weather, lighting, damage and explicitly sanctioned story consequences may change.

## 5. Persistent continuity states

Story consequences may create derived character states without changing identity.

The Week 2 barbershop event establishes the reference implementation:

- `TDS_PRE_HAIRCUT_v1`: exact canonical Podium Shadow with intact dreadlocks.
- Page 13: haircut event occurs.
- `TDS_POST_HAIRCUT_v1`: same species, face/head architecture, scales, body, equipment and identity; only the sanctioned hair state changes.
- From Page 14 forward, any TDS appearance MUST resolve to the post-haircut state unless a later story explicitly changes it.

Derived states are additive continuity overlays. They never replace the master identity packet.

## 6. Character QA — hard gate

Every relevant page receives explicit PASS/FAIL for:

- OWNER MATCH
- REFERENCE LIKENESS
- SPECIES
- BODY ARCHITECTURE
- HEAD / FACE
- WARDROBE
- SIGNATURE FEATURES
- COMPANION / PROP
- CONTINUITY STATE
- CROSS-CHARACTER CONTAMINATION
- RETIRED CHARACTER / RENAME SAFETY

Any single FAIL = `PAGE_REJECT`. There is no weighted average and no visual-quality exception.

## 7. Fact Lock is independent

Character authority is never factual authority.

Scores, records, standings, matchups, schedules, rosters and transactions MUST resolve independently through Flaim/approved league data before publication.

`CHARACTER_PACKET_LOCK != FACT_LOCK`

Both gates are mandatory.

Generative art must not be trusted to render deterministic league facts. Where a factual text layer matters, prefer deterministic typography/layout or reject/regenerate after exact QA.

## 8. Repair doctrine

Existing pages are classified:

- **PASS** — survives all applicable gates.
- **PATCH** — underlying page is excellent and defect is isolated; surgical repair is permitted.
- **REGENERATE** — identity, matchup mapping, factual data, continuity or composition is structurally compromised.

No page is grandfathered because it looks good.

## 9. Acceptance-test colophon rule

A final Ledger/colophon may report PASS only from completed QA evidence. It may never self-certify anticipated results.

Final sequence:

`REFERENCE_LAYER_PASS → FACT_LOCK_PASS → PAGE_REMEDIATION → FULL_PAGE_AUDIT → LEDGER_GENERATION → PDF_ASSEMBLY → RENDER_AUDIT → PUBLICATION_APPROVAL`
