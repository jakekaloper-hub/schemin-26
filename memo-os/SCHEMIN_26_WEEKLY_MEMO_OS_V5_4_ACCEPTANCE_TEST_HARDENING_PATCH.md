# SCHEMIN '26 WEEKLY MEMO OS — V5.4 ACCEPTANCE-TEST HARDENING PATCH

**Status:** BINDING
**Authority:** Weekly Memo OS / Bullpen
**Origin:** Full Week 2 blank-canvas test + remediation loop, 2026-09-27
**Purpose:** Convert observed production failures into permanent controls for all future weekly memos.

## 1. What the Week 2 test proved
The multi-page narrative format is approved as a production direction: matchup stories may span multiple pages and should create persistent locations, objects, humiliations, consequences and callbacks.

The test exposed five systemic failure classes: character drift despite correct prose; generative corruption of deterministic league data; continuity resets between pages; aspect-ratio/mobile presentation drift; and premature QA certification.

## 2. Source hierarchy and two-lock rule
Every run creates two independent immutable inputs before creative generation.

FACT_LOCK: Refresh from Flaim/canonical league source immediately before pre-production. Lock league/team IDs and names, completed scores, records/PF/PA when used, upcoming schedule, roster/transaction/waiver facts used editorially, and derived arithmetic.

CHARACTER_LOCK: Load the commissioner-approved 12-owner master reference plate plus Character Canon v2 and continuity overlays.

FACT_LOCK and CHARACTER_LOCK are independent. Neither substitutes for the other.

## 3. Deterministic typography firewall
Image generation MUST NOT be trusted as system of record for scores, records, standings, schedules, bids, transaction amounts, exact names, rankings, calculated margins, or QA status.

For data-bearing pages use: ART_BACKGROUND -> DETERMINISTIC_TEXT_COMPOSITE -> FACT_QA.

If generated art contains factual text, it is untrusted until exact QA. A single wrong deterministic fact blocks PAGE_LOCK. Repeated regeneration to obtain exact data text is prohibited when deterministic composition is available.

## 4. Character reference enforcement
V5.3 remains fully binding. Every owner appearance resolves OWNER -> MASTER REFERENCE CROP -> CHARACTER_PACKET -> CONTINUITY_STATE -> GENERATION.

The master lineup is absolute visual authority. Team-name semantics are forbidden as a visual identity source.

Critical negative locks: Trade Jedi has no championship belt; D0nkey K0ng is the Arsenal Centaur and never gorilla/ape/human-only barbarian; TDS is one reptilian humanoid and never three snakes/three-headed snake/Medusa/human; El Niño is a nonhuman weather elemental; Mud Dogs is a monstrous swamp canine; Duckhook is an anthropomorphic white duck golfer.

## 5. Continuity ledger
Every issue maintains a CONTINUITY_LEDGER before Page 1 and updates it after each locked page. Track character physical state, persistent equipment/wardrobe, story-relevant damage/mud/hair changes, environmental damage, named artifacts, established geography, recurring world jokes, and team-renames without redesign.

A later page may not silently reset a locked state. Week 2 reference case: TDS begins with intact dreads; the haircut creates a derived state; Page 14+ uses the post-haircut state until narratively changed.

## 6. Story architecture doctrine
A matchup is not limited to one recap card. Allocate pages by narrative need. Preferred three-beat grammar when warranted: SETUP/JOURNEY/PROVOCATION -> CLIMAX/SCORE EVENT -> AFTERMATH/CONSEQUENCE.

Illustration-to-copy ratio should vary intentionally. Quiet setup/aftermath pages may carry 300–700 words; climax pages may be 90–95% art with minimal prose. Objects and locations should persist across future issues.

## 7. Native mobile page contract
Primary target is a typical iPhone/Apple mobile PDF viewer. Default master is portrait approximately 9:16, one native ratio across the issue unless explicitly approved, no destructive crop/stretch, protected edge-safe zones, and body copy checked at actual phone viewing scale. Locked page masters remain immutable during assembly. Unapproved landscape/alternate-ratio output is PAGE_REJECT.

## 8. Page production state machine
PAGE_BRIEF -> FACT_SCOPE -> CHARACTER_SCOPE -> CONTINUITY_SCOPE -> COMPOSITION -> COPY -> ART -> DETERMINISTIC_DATA_LAYER -> FACT_QA -> CHARACTER_QA -> CONTINUITY_QA -> MOBILE_QA -> ORIGINALITY_QA -> PAGE_LOCK.

Failure at any required gate returns the page to PATCH or REGENERATE. Do not advance because an image exists.

## 9. PATCH vs REGENERATE
PATCH when composition/storytelling are strong and an isolated defect can be surgically corrected without compromising reference fidelity.

REGENERATE for wrong character/species/body architecture, wrong matchup mapping, retired identity contamination, multiple factual errors, wrong aspect ratio, or structurally wrong continuity.

No visual-quality exception.

## 10. Ensemble and map safeguards
Multi-character pages have elevated drift risk. Resolve every owner independently; attach approved references; never let one generic prompt infer the cast; reduce simultaneous characters if fidelity cannot be maintained; prefer artifacts/banners/geography/deterministic labels over incorrect cameos.

World maps must not invent retired team names, records, standings or owner identities.

## 11. Editorial arithmetic QA
Derived claims require explicit calculation from FACT_LOCK: closest/largest margin, high/low score, post-week record, streak, aggregate/ledger totals. Store the calculation in QA evidence. Never infer visually or copy from an older memo.

## 12. Acceptance ledger / colophon
The final QA ledger is generated LAST and reports evidence, not aspirations. Allowed statuses: PASS, FAIL, PASS WITH DOCUMENTED LIMITATION.

No category is PASS until the final assembled/rendered issue is inspected. Any upstream page change invalidates affected certification until rerun.

## 13. PDF assembly contract
Assembly is mechanical: locked page masters only; preserve order and native ratio; no redesign/reflow/crop/stretch; verify page count; render every final PDF page; inspect clipping, blanks, glyph failures, compression damage and sequence.

Only the rendered final PDF receives PUBLICATION_APPROVAL.

## 14. Blank-canvas benchmark discipline
For tests against an existing memo, the old memo may provide facts, commissioner directives and later benchmark comparison, but not composition templates during blank-canvas generation. Compare old vs new only after the new candidate is complete.

## 15. Future weekly run sequence
DATA_REFRESH -> FACT_LOCK -> CANON_LOAD -> CHARACTER_LOCK -> CONTINUITY_LOAD -> STORY_ROOM -> PAGE_MAP -> PAGE-BY-PAGE PRODUCTION -> PAGE_LOCKS -> FULL ISSUE AUDIT -> LEDGER -> PDF ASSEMBLY -> RENDER AUDIT -> PUBLICATION_APPROVAL -> CONTINUITY_LEDGER UPDATE.

## 16. Week 2 test disposition
The 2026-09-27 Week 2 blank-canvas run is an acceptance-test artifact, not a clean publication master. Its value is diagnostic. Its failures are now permanent controls through V5.3 and V5.4.

Retain: illustration-first cinematic worldbuilding; multi-page matchup chapters; quiet pages around spectacle; persistent artifacts/geography; literary copy beyond recap blurbs; recurring departments inhabiting one world; native mobile-first design.

**Future standard: story ambition may increase, but factual and character precision may never decrease.**
