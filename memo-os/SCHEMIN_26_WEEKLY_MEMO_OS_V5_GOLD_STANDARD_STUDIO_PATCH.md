# 2. V5 PRIME DIRECTIVE

A Pro Schemin’ weekly memo is not a score report with decorative artwork.

It is a **fictional sports publication built from real fantasy-football evidence**.

Every issue must feel:

- reported;
- illustrated;
- league-specific;
- cinematic;
- tactile;
- humorous;
- continuous with prior league history;
- readable on a phone;
- unmistakably Pro Schemin’.

A page fails the Schemin’ standard when it could be repurposed for two random fantasy teams with only the names changed.

A page also fails when the text is removed and the illustration no longer communicates the characters, conflict, or result.

The Weekly Memo OS may never trade away league identity merely to produce something safe, generic, or easy to assemble.

# 3. THE V4 FAILURE THAT V5 CORRECTS

The failed Week 2 OS test exposed a new class of system error:

> **Defensive degradation.**

The system correctly avoided fabricating unavailable information, but then degraded the product into a safe modular report that did not resemble the approved Schemin’ publication.

V5 establishes:

> Missing inputs may reduce factual scope.  
> They may not silently reduce the publication into a generic dashboard.

If required inputs for premium production are unavailable:

- continue all unaffected production work;
- mark the dependent stage `BLOCKED`;
- attempt approved retrieval paths;
- request the missing input from Jake when necessary;
- do not substitute generic characters, generic visual language, fake details, or a lower-quality publication mode without explicit editorial reason.

**Safe is not the same as publishable.**

# 5. PRODUCTION MODES

## MODE A — MODULAR EDITORIAL MODE

Build page components separately:

```text
approved art
+ live typography
+ verified data
+ editorial layout
= final page
```

### Use Mode A when:

- dense numerical accuracy dominates;
- late factual changes are likely;
- exact selectable text is important;
- a table or ledger needs easy correction;
- integrated generated typography would create excessive risk.

### Appropriate candidates

- unusually dense standings;
- schedule matrices;
- transaction appendices;
- complex stat tables;
- data-heavy reference pages.

### Mode A risk

Mode A can become:

- PowerPoint-like;
- SaaS-like;
- dashboard-like;
- visually disconnected from the issue.

Therefore Mode A still requires **worldbuilding and editorial art direction**.

---

## MODE B — PREMIUM ILLUSTRATED PAGE MODE

The page is conceived as one editorial composition:

```text
story
+ exact characters
+ environment
+ action
+ props
+ headline hierarchy
+ score / record information
+ narration zone
+ visual jokes
+ physical receipts
= one integrated magazine page
```

### V5 default

Use Mode B by default for:

- cover;
- Opening Drive;
- matchup features;
- Power Rankings when visually embedded into the world;
- Pittsy’s Book;
- State of Play;
- Waiver Wire;
- Final Word;
- major recurring departments;
- any page whose value depends on atmosphere, comedy, character, or story.

### Required visual standard

Mode B pages should normally use:

- portrait full-page composition;
- 50–70% visual action / environment;
- 20–35% headline / narration zone;
- 5–15% metadata / folio / small jokes;
- tactile physical materials;
- cinematic practical lighting;
- clear focal action;
- protected text zones;
- phone-readable hierarchy.

The page should feel like it exists **inside the Pro Schemin’ universe**.

# 7. FACT STATES

Every material claim must exist internally as one of:

```text
VERIFIED
DERIVED
EDITORIAL
UNVERIFIED
```

### VERIFIED
Directly supported by trusted evidence.

### DERIVED
Mathematically calculated from verified evidence.

### EDITORIAL
Interpretive language based on verified or derived facts.

### UNVERIFIED
Not safe to publish as fact.

The editorial team may never convert `UNVERIFIED` into “probably true.”

Character continuity is franchise continuity.

```text

```

## Character evidence hierarchy

1. user-supplied canonical owner / team artwork;
2. previously approved owner spotlight / character reference;
3. approved prior memo artwork;
4. written Character Packet description.

The image reference is authoritative.

Text description supports it.

Text does not override the reference.

## Automatic Character QA failures

- species changes;
- human becomes animal or vice versa;
- D0nkey becomes a gorilla;
- Mud Dogs becomes a normal household dog;
- established owner character becomes a generic mascot;
- rebrand changes character identity;
- signature silhouette disappears;
- essential props / wardrobe identity disappear;
- character is too small to recognize;
- matchup feature omits one required combatant;
- wrong character appears in a utility-page miniature.

### Missing character reference rule

If the system cannot reliably retrieve the canonical reference:

```text
CHARACTER ASSET = BLOCKED
```

Do **not** solve the problem by creating a generic substitute.

Data, writing, Story Cards, and page architecture may continue while art waits.

# 15. GENERATED TYPOGRAPHY POLICY

Premium Illustrated Page Mode may contain integrated generated typography.

- player name;

- wager;
- FAAB value;
- receipt;
- board label.

Also inspect:

- invented words;
- malformed logos;
- nonsense labels;
- incorrect jersey / sign text;
- accidental substitutions.

### Corrective action

**PATCH** when:
- isolated;
- visually safe;
- patch will not look pasted on.

**REGENERATE** when:
- central text is wrong;
- character is wrong;
- several fields are wrong;
- headline is malformed;
- hierarchy is broken.

**REBUILD FROM STORY CARD** when:
- concept itself is generic;
- page duplicates another page;
- story does not justify the scene.

# 20. ERROR TAXONOMY

## A. Factual defect
Examples:
- wrong score;
- wrong record;
- wrong standing;
- wrong opponent;
- bad derived margin.

Response:
- patch if isolated;
- rebuild if fact drives the page.

## B. Character defect
Examples:
- wrong species;
- generic substitute;
- rename changes character;
- missing focal character.

Response:
- regenerate.

## C. Narrative defect
Examples:
- score restatement;
- generic sportswriting;
- repeated story function;
- unsupported causality.

Response:
- rewrite Story Card.

## D. Editorial-design defect
Examples:
- SaaS dashboard;
- PowerPoint page;
- body text covers action;
- no environmental worldbuilding.

Response:
- rebuild page architecture.

## E. Redundancy defect
Examples:
- State of Play duplicates scoreboard;
- Final Word repeats awards;
- multiple pages tell same joke.

Response:
- merge, delete, or reassign editorial job.

## F. Generated-text defect
Examples:
- spelling;
- malformed stat;
- wrong label;
- nonsense receipt.

Response:
- patch when isolated;
- regenerate when central.

## G. Defensive-degradation defect
Examples:
- character assets missing, so page becomes generic;
- incomplete data causes whole issue to become a sterile report;
- art uncertainty causes fallback to dashboard design.

Response:
- block the affected dependency;
- retrieve / request missing input;
- preserve premium architecture elsewhere.
