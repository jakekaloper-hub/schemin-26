# WEEK 4 LIVE PRODUCTION SALVAGE PROTOCOL

**Status:** CONTROLLING OVERLAY FOR REMAINING WEEK 4 PRODUCTION
**Goal:** finish a publishable Week 4 Memo without requiring the Commissioner to manually art-direct every page.

## North Star

Jake should be able to say:

`generate page N`

and receive a candidate whose:
- page role;
- chapter role;
- camera;
- composition family;
- exact copy;
- character references;
- result treatment;
- continuity;
- typography zones

were already decided before rendering.

## Major workflow change

The old unit of production was:

`one page`

The new unit of production is:

`one chapter / one module family`

Before any first page of a remaining three-page matchup is rendered, Bullpen must resolve all three pages together.

That means Pages 11–13 are preflighted as one golf chapter.
Then Pages 14–16 as one man-cave chapter.
Then Pages 17–19 as one institutional-finance chapter.
Then Pages 20–22 as one disaster-comedy chapter.

The renderer never receives an isolated page without knowledge of the other pages in its chapter.

## Mandatory production layers

### Layer A — fixed issue shell
All remaining pages use one fixed issue shell:
- canonical portrait ratio: **1024×1536**;
- fixed top masthead geometry;
- fixed Week 4 / date area;
- fixed title-safe zone;
- fixed body-copy safe zones;
- fixed lower result-module safe zone when applicable;
- cream / aged-gold / near-black editorial palette.

The renderer does not redesign this shell per page.

### Layer B — art only
The image model's primary job becomes:
- character action;
- environment;
- lighting;
- camera;
- props;
- visual comedy/drama.

It does **not** own:
- exact team names;
- scores;
- records;
- rankings;
- issue metadata;
- betting math;
- manuscript copy.

### Layer C — deterministic publication typography
Exact reader-facing copy comes from:
`WEEK_04_FINAL_WRITTEN_MANUSCRIPT.md`

Exact factual fields come from Fact Lock.

Publication Design composites these fields after art.

### Layer D — reusable result strip
Pages 13, 16, 19 and 22 use the same result-strip grammar already established conceptually by the DK/Obi and TDS/Mud result pages:

- left: winner / record / score;
- center: restrained `DEF.`;
- right: opponent / record / score;
- optional bottom margin line;
- same geometry, typography scale and border language across all result pages.

Only colors / character thumbnails may adapt by matchup.

The image model never generates the score digits.

## Chapter preflight rule

Before rendering Page 11, Bullpen must approve Pages 11–13 together.

For each chapter, define:

1. **SETUP PAGE**
   - establishes place and comic/dramatic premise;
   - wider camera;
   - no result treatment.

2. **ESCALATION PAGE**
   - visibly changes camera and action;
   - cannot repeat the setup composition;
   - no result treatment.

3. **PAYOFF / RESULT PAGE**
   - changes time, staging or social state;
   - uses result strip;
   - closes with durable object / consequence.

If the three pages do not look meaningfully different in thumbnail view, the chapter fails before rendering.

## Commissioner intervention budget

Target: **0 factual/canon/layout corrections per page**.

A Commissioner request such as:
- change the creative emphasis;
- make action bigger;
- choose a different emotional beat

is a creative preference.

A Commissioner correction such as:
- wrong team;
- wrong character;
- wrong score;
- wrong GOTW status;
- repeated page composition;
- wrong manuscript;
- wrong body plan

is a Bullpen production defect and must be logged as such.

## Candidate policy

Because native image generation surfaces candidates in chat, Bullpen cannot hide a failed raster.

Therefore:
- pre-render control must be much stricter;
- a surfaced candidate is visibly labeled either `CANDIDATE` or `APPROVED`;
- Bullpen should immediately self-reject objective failures without waiting for Jake to point them out;
- the next attempt should preserve what worked instead of restarting from scratch.

## Salvage policy for Pages 1–10

Do not automatically regenerate all early pages.

Before final assembly:
- normalize aspect ratio;
- remaster Page 2 to the locked final manuscript;
- remaster Page 3 to a clean deterministic board;
- fix any exact team-name chrome drift on Pages 4–7;
- certify DK/Obi anatomy and continuity;
- independently recheck TDS Pages 8–10 for one-body / exactly-three-head anatomy;
- rebuild only structurally failed hunting pages;
- replace generated result digits with deterministic result modules.

This is cheaper and safer than throwing away the strongest existing art.
