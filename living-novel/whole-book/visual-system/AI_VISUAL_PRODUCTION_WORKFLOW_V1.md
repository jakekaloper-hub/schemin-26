## Map production
Atlas geometry/data → deterministic vector/diagram skeleton → art-direction pass → AI terrain/material enhancement where helpful → external labels → Atlas QA.

AI may beautify the map. It may not decide where places are.

## Character production
Current state remains fail-closed.

When character gate eventually opens:
OWNER → CHARACTER PACKET → owner-specific reference → subject-bound generation → output-instance receipt → independent Character QA → composition.

No text-only workaround.

## Page template production
For each final page, generate 2–4 *layout concepts* before finished art only when the visual problem is nontrivial. Compare:
- reading path;
- prose legibility;
- art contribution;
- page-turn behavior;
- relation to adjacent pages.

Once a composition family is chosen, do not generate decorative alternatives endlessly.

## Reuse architecture
A locked environment/map can be:
- full plate;
- cropped margin;
- chapter opener background;
- appendix map;
- digital Atlas link target.

Reuse the same governed source asset; do not independently regenerate continuity-critical geography for every surface.

## Memo ↔ Novel reuse
Memo final raster is not automatically inserted into Novel.
Instead:
Memo receipt → identify durable story contribution → hydrate current Atlas/canon → recompose for book aspect/reading job → Novel QA.

## QA automation opportunities
Build future validators for:
- map LOC/ROUTE presence;
- current-character-version receipt;
- forbidden retired identity terms;
- deterministic-data placeholders vs final text;
- adjacent-template repetition;
- missing world-state timestamp;
- stale Memo-derived asset provenance.
