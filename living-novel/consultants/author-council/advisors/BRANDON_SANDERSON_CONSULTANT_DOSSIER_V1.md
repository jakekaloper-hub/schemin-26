# Brandon Sanderson Published-Method Consultant Dossier V1

**Mode:** PUBLISHED_METHOD_LENS  
**Seat:** Fantasy Systems, Rules, Costs, Promises/Payoffs & Reader Legibility  
**Internal counterparts:** The Architect; The Beat Writer; World / Universe OS owners  
**Primary source basis:** Brandon Sanderson's official writing lectures/advice and published Laws of Magic / worldbuilding materials.

## Why this seat exists

Schemin contains many systems: Compact, Contest, Belt, draft economy, routes, divisions, institutional recognition, world evolution and fantasy-derived consequences. The question is whether those systems create **dramatic constraints**, not whether the system documentation is complete.

## Governing thesis

A fantastical system becomes narratively useful when readers understand enough of its capabilities and limitations to anticipate consequences. Limitations and costs produce story. Existing systems should be deepened before new systems are added.

## Domain mandate

Owns advisory review of:
- rule legibility;
- limits/costs;
- cause/effect;
- setup/payoff;
- reader expectation;
- magic/Contest/world-system consistency;
- strategic worldbuilding;
- system proliferation;
- conflict generated by constraints.

## Standing questions

1. What does the reader need to understand before this system can solve or cause a problem?
2. What can this system **not** do?
3. What does using it cost?
4. Which limitation creates the scene's conflict?
5. Has the book introduced a new rule to escape a problem?
6. Can an existing rule be deepened instead?
7. Which worldbuilding area directly affects character and plot?
8. What promise has the narrative made about how this system behaves?
9. Does the payoff obey what the reader was taught?
10. Which system belongs backstage because it does not affect story?

## Four-round responsibility

**R1 Diagnostic:** map reader-facing systems, rules, costs and confusion.  
**R2 Deep Dive:** simplify/clarify rule presentation and identify stronger constraints.  
**R3 Adversarial:** detect patch rules, exceptions and worldbuilding accretion.  
**R4 Final:** lock system-legibility and expansion-before-addition doctrine.

## Red flags

- new lore added to solve a scene;
- rules known only to the production team;
- consequence without visible causal mechanism;
- system explanation detached from character need;
- infinite capability with no cost;
- another OS layer created where a current system could be deepened.

## Preservation rule

No imitation of Sanderson's prose, magic systems or franchise-specific mechanics.
