# Reviewed profile composition consumer

A03 adds a distinct consumer, not an exception to environment artwork restrictions. `load_compositions(root, output, revision)` returns `{schemaVersion: 1, assets: {CHAR_ID: {file, alt, width, height, sha256, reviewUrl}}}` and copies immutable verified bytes under `output/character-compositions/`. The existing `load_artwork` character rejection stays unchanged. No generation is invoked or authorized; presentation art never replaces primary canon.

`ACCEPTED_CHARACTER_COMPOSITIONS.json` is the explicit repository-reviewed publication allowlist. It is empty because no actual reviewed compositions are supplied. There is a working positive synthetic fixture path; this is not an unconditional HOLD implementation. No directory discovery or inventory status automatically creates an accepted entry.

Each accepted entry pins three repository-relative JSON files and exact SHA-256 hashes: `packet`/`packetSha256`, `executionReceipt`/`executionReceiptSha256`, and `reviewReceipt`/`reviewReceiptSha256`.

The packet contains one canonical `characterId`, `scope: PROFILE_PRESENTATION_ONLY`, `assetPath`, `assetSha256`, reviewed `alt`, and `reference: {path, sha256, sourceKind, filename, assetId?}`. The reference must be the current registered source path and actual bytes; the existing `reference_authority.validate_reference_candidate` rejects derived, stale and active-conflict sources. This initial consumer supports the byte-bound reference path, not a new native-library attestation format.

The packet also records the original `requestId`, `route`, `mountReceiptId`, `generationReferenceId`, `subjectBindingId`, and `outputInstanceId`. The execution JSON must have the existing governed-generator result shape: `GENERATION_EXECUTED_PENDING_CHARACTER_QA`, `renderer_invoked: true`, matching output instance, and exact `execution_receipt` request/route/mount/reference/subject lists. A blocked or unrendered job is never promoted by a presentation review.

The independent review JSON binds `packetSha256`, `executionReceiptSha256`, `characterId`, `outputInstanceId`, `assetSha256`, and `referenceSha256`; records distinct nonempty `reviewer` and `preparedBy`; uses `decision: ACCEPTED_FOR_PROFILE_PRESENTATION`, the same profile-only scope, and checks `{identity: PASS, sourceBinding: PASS, composition: PASS, mobileCrop: PASS}`. These are the consumer's presentation acceptance fields, not a new canon approval authority.

Hashes prove byte consistency; names and status strings do not authenticate people or prove a provider call occurred. The trusted activation boundary remains actual repository review of the allowlist and its evidence under existing authority. A legitimate entry requires real governed-generation evidence plus independent visual review; no such entry is added here. The consumer does not mint, replay, validate an expired runtime eligibility token, or replace the upstream generation eligibility gate. Synthetic fixtures exercise the contract only in temporary directories and cannot activate production art.

All entries are validated before any new output is copied. Path/symlink escape, malformed receipts, missing hashes, stale references, swapped bindings, self-review, duplicate IDs, corrupt raster and altered source bytes fail the build. A generated ownership marker records copied filenames/hashes. On a subsequent successful build, all previously owned bytes are verified and removed before writing the new accepted set; an empty registry therefore removes revoked art from the generated folder, not just the catalog. Symlink targets, source artifacts under the target, unknown files or modified owned bytes block cleanup rather than delete user work. The marker is bookkeeping, not approval evidence. The profile consumer owns UI layout and accessible presentation separately.
