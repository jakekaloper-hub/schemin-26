# CHARACTER VISUAL LOCK GATE
## Binding Chronicle Production Rule

**Status:** BINDING — effective immediately
**Trigger:** Prologue Page 1 character-drift failure

## Bullpen finding
The failed Prologue attempt was a production architecture failure. A single generative composition was asked to render twelve distinct canonical inhabitants without twelve individually validated visual-reference packets. Several characters drifted. This cannot be allowed on Page 1.

## Hard rule
**No canonical character may receive a clear face/body depiction in publication art until that character has a Visual Lock Packet.**

A text description alone is insufficient for ensemble generation when exact visual continuity matters.

## Visual Lock Packet
Each of the twelve requires: owner; canonical character identity; current team name; approved visual reference image(s) where available; immutable physical traits; wardrobe/armor traits; signature props; companion rules; forbidden mutations; rename history separated from appearance; recognition test; approval status.

Statuses: LOCKED; TEXT-LOCKED; PROVISIONAL; BLOCKED.

## Generation policy
LOCKED characters may appear clearly using approved references.
TEXT-LOCKED or PROVISIONAL characters may use verified names, canon-safe objects, environmental traces, or intentionally ambiguous/distant presence, but no prominent clear face/body depiction.
BLOCKED characters are not depicted.

## Ensemble rule
Never ask an image model to independently invent twelve canonical designs from names or prose. Compose from individually locked references/assets or intentionally avoid full depictions. Recognition outranks spectacle.

## Page 1 correction
The failed twelve-portrait treatment is rejected and non-canon. Jake / Trade Jedi may serve as POV anchor only from locked visual authority. The other eleven are established as presences through the Archive/world rather than invented portraits. Page 1 prose establishes twelve inhabitants without requiring twelve bodies. Page 2 deepens evidence/history rather than becoming a roster-card page.

## QA
Before rendering any page, Character QA produces a manifest mapping each character to lock status, reference and allowed depiction. Any clear depicted character lacking LOCKED status blocks the render.

After rendering, face/head, species/body, silhouette, wardrobe, props, companions and identity resolution are checked. Major mismatch requires regeneration.

## First-impression rule
Cover, Prologue opening, chapter opener and first appearance receive stricter QA than routine later appearances. A character's first published appearance must never be the place where the model invents the character.
