## Core ruling
The Living HTML is the CONTAINER. The Novel AI-OS is the PAGE FACTORY.

The OS MUST produce the released novel one designed page/spread at a time. A CSS theme, generic parchment template, repeated illustration pool, or conventional ebook layout is not an acceptable substitute for spread production.

## Permanent product
The reader opens one stable artifact:
novel/book/SCHEMIN_LIVING_BOOK.html

That artifact contains every APPROVED released spread in reading order.
The same path is replaced in place after every approved addition.
PDF is generated from this Living HTML for print/archive.
Markdown remains canonical released prose and visual-placement/source metadata.

## Spread production loop
For EACH spread:
1. Select the exact released prose assigned to the spread.
2. Build a spread scene contract: POV, location, time, emotional beat, physical action, revealed information, continuity constraints.
3. Load Story Bible and current narrative state.
4. Load Master Character Canon for every source-derived principal present.
5. Verify original Story Canon characters are NOT silently mapped to league owners.
6. Visual Director creates a bespoke composition plan.
7. Decide visual hierarchy: full-page painting, partial painting, map, artifact, sketch, marginal note, seal, rubbing, botanical/environmental study, negative space, title/folio.
8. Generate only the art components required by THIS spread.
9. Composite those components with REAL TYPESET MANUSCRIPT TEXT. Generated-image typography is decorative only and may never replace prose.
10. QA character identity, geography, clothing, props, time of day, chronology, scene action and low-magic constraints.
11. QA text readability, no missing prose, no duplicated prose, no accidental rewriting, no clipping, orphan/widow problems or art obscuring text.
12. Reader Simulator checks whether art deepens rather than merely repeats prose.
13. Umpire compares the finished spread against the author-supplied reference standard.
14. If any MAJOR defect exists: REJECT and regenerate/recompose.
15. If PASS: freeze spread asset + manifest and append to Living HTML.
16. Continue automatically to next spread.

## Required spread aesthetic
The author-supplied reference is the benchmark:
- physical open-book feeling;
- worn leather/paper edges and tactile parchment;
- illustration is part of page architecture;
- cinematic environmental painting can consume most of a page;
- prose sits in deliberately protected negative space;
- maps, field sketches, artifacts, stone rubbings, seals, handwritten notes and environmental fragments create secondary storytelling;
- illuminated/drop-cap treatment where appropriate;
- elegant chapter hierarchy and folios;
- visual continuity across adjacent spreads;
- every spread may have a different composition while remaining one coherent edition;
- no generic fantasy filler;
- no rectangular image dropped above/beside ordinary text;
- no repeated art merely to fill space.

## HTML architecture
The HTML MUST NOT manufacture spreads dynamically from one generic chapter template.
Instead it is an ordered manifest of individually approved spread modules:
- spread ID
- manuscript range
- scene contract ID
- approved visual asset IDs
- layout class unique/selected for the spread
- accessibility alt text
- continuity/version metadata
- approval status

Only PASS spreads render in the RELEASED reader.
Unreleased Week 3 spreads live under novel/book/production/week_03/ and cannot appear in the public Living HTML.
