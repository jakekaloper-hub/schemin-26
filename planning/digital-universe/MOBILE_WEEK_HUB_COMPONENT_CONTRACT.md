# Mobile Week Hub — Component Contract v0.1

## Route
`/season/2026/week/2`

## Experience order
1. **WeekHero** — cover-derived cinematic surface, week/title, mute, reduced-motion safe.
2. **FastFactsRail** — six finals immediately accessible.
3. **OpeningDrive** — commissioner/editorial framing.
4. **GOTWChapter** — hero motion + verified result + narrative.
5. **LeagueState** — standings / power rankings / evidence.
6. **MatchupChapter × 6** — bespoke environment per matchup.
7. **PittysBook** — editorial betting ledger isolated from league truth.
8. **WaiverWire** — transaction/evidence module.
9. **CharacterArcUpdates** — week-to-week consequences.
10. **NextWeekHook** — upcoming board.
11. **OriginalEdition** — immutable PDF entry.
12. **ProvenanceDrawer** — source/freshness/edition status.

## Component API doctrine
All components consume WSP fields; none fetch ESPN independently. Media is optional enhancement: factual HTML renders even if all generated media fails.

## Mobile budgets
- Hero poster before video.
- No autoplay audio.
- Lazy-load chapters below fold.
- Reduced-motion mode replaces cinematic transforms with stills/fades.
- Captions/transcripts for narration.
- Core score/story content usable before heavy media arrives.

## Visual rule
No generic SaaS cards. UI surfaces should inherit Week 2's physical editorial language: paper, evidence, signage, desk objects, banners and cinematic environments while retaining semantic HTML.
